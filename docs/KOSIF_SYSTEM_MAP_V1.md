# KOSIF System Map v1

## الهدف
تحويل KOSIF من مجموعة شاشات/كتب/وكلاء متجاورة إلى نظام واحد له **مصدر حقيقة مركزي** يربط تجربة الاستخدام، الكتب، المصادر المهنية، المحاسبة، المراجعة، مجلس المراجعين، والأدلة.

## المبادئ الحاكمة
1. صحة الأرقام قبل السرعة والذكاء الاصطناعي.
2. المصدر الرسمي أعلى من الكتاب التدريبي أو شرح AI.
3. كل استنتاج مهني يحمل: الدولة + الفترة + حالة النفاذ + المصدر + موضع المرجع.
4. لا يُفقد النص الأصلي للكتاب أثناء التنظيف؛ كل كتلة تحتفظ بالصفحة/السطر والمادة الخام.
5. إزالة التكرار تكون محافظة: التكرار الدقيق/الهيدر/الفوتر فقط آلياً، وما عداه يُعلّم للمراجعة.
6. الذكاء الاصطناعي استشاري؛ القيود النهائية، الأهمية النسبية، المطابقات والرأي النهائي لها حوكمة حتمية/بشرية.
7. تجربة «مفاتيح الثروة» أصل محفوظ؛ لا تُكسر أو تُستبدل بنسخة قارئ ناقصة.

## الطبقة 1 — Experience Shell

### الشاشة الرئيسية
- وحدات واضحة: المراجعة، الكتب، مفاتيح الثروة، لوحة المبيعات، عقل النظام.
- بطاقات أصغر وأكثر انتظاماً من الإصدارات القديمة.
- هوية واحدة: KOSIF Editorial/Kitab مع Themes محفوظة من التجارب السابقة.
- RTL افتراضي، دعم EN/IT/HI ثم اللغات الإضافية.
- حالة PWA واضحة: مثبت / متاح للتثبيت / iOS يحتاج Add to Home Screen.

### قواعد iPhone/WebKit
- الـModal/Drawer له scroll مستقل ولا يحرك الخلفية.
- `overscroll-behavior` وscroll lock يطبقان على shell لا على viewport بالكامل.
- لا bottom bar تمنع المحتوى.
- safe-area للـtop/bottom.

## الطبقة 2 — Unified Book Engine

المحرك: `src/engine/book-engine-v1.mjs`

### الإدخال
- نص مقسم إلى صفحات `text-pages`.
- TXT.
- JSON منظم.
- PDF لا يدخل مباشرة إلى محرك الكتاب: يمر أولاً بطبقة استخراج تحفظ رقم الصفحة والنص الخام، ثم يمر الناتج إلى Book Engine.

### مراحل المعالجة
1. حفظ النص الخام.
2. Normalize Unicode والمسافات وعلامات RTL/LTR الخفية.
3. إزالة سطر رقم الصفحة إذا كان مستقلاً.
4. اكتشاف الهيدر/الفوتر المتكرر عبر الصفحات وإزالته من النص المقروء مع حفظه في `removedArtifacts`.
5. إزالة التكرار النصي **الدقيق** فقط، لا fuzzy deletion.
6. اكتشاف بنية: باب → فصل → قسم/مبحث/مطلب → عنوان → فقرة/بند.
7. وضع Flag على OCR المشكوك فيه بدلاً من اختراع تصحيح.
8. توليد `outline` وفهرس بحث.
9. الاحتفاظ بـ`raw`, `page`, `line` في كل Node.

### مخرجات Schema
`kosif.book.v1`

كل Node يحتوي على:
- `id`
- `type`
- `text`
- `raw`
- `source.page`
- `source.line`
- `path`
- `flags`

### سياسة فتح الكتب
- لا شاشة وسيطة بكتاب آخر.
- الكتاب المطلوب يفتح مباشرة داخل القارئ الموحد.
- أدوات Mixer/AI/Library لا تكون الشاشة الافتراضية؛ تبقى أدوات جانبية عند الحاجة.
- «مفاتيح الثروة» يبقى له payload الأصلي وتجربة القراءة الأصلية.

## الطبقة 3 — System Brain / Knowledge Authority

واجهة: `public/system-brain-v1.js`

مصدر الحقيقة: `public/data/kosif-system-brain-v1.json`

### سلم السلطة
1. الجهة الرسمية المحلية المختصة.
2. الجهة الدولية المصدرة للمعيار.
3. النسخة المعتمدة/المرخصة داخل KOSIF.
4. إرشاد/توضيح رسمي.
5. كتاب أو مادة تدريبية.
6. شرح AI.

### حالة المصدر
- `effective`: نافذ ضمن الدولة/الفترة.
- `future-effective`: قادم النفاذ.
- `exposure-draft`: مشروع للتعليق، لا يعامل كإلزام.
- `superseded`: تاريخي.
- `training`: شرح فقط.

### السعودية
الأولوية: SOCPA → ZATCA بحسب الموضوع → IFRS Foundation/IASB → IAASB، مع الفصل بين الاعتماد المحلي والمصدر الدولي.

### الكتب الداخلية الحالية
- `b3`: معايير IFRS الكاملة المحدثة 2025 — مرجع رسمي محدث.
- `b1`: إصدار 2018 — مرجع تاريخي.
- `b2`: DipIFR — تدريب.
- `b4`: مفاتيح الثروة — تطوير/قراءة، ليس سنداً مهنياً.

### Source Intelligence
يبقى `src/v38-source-intelligence.js` مسؤولاً عن:
- سجل المصادر.
- طبقات الثقة.
- كشف التغيير المقنن.
- حفظ تاريخ البصمات.
- عدم جلب/إعادة نشر نصوص محمية كاملة.

## الطبقة 4 — Accounting & Audit Engine

### المرحلة 1: Engagement Context
المدخلات:
- الدولة.
- الفترة.
- نوع المنشأة.
- إطار التقرير.

المخرجات:
- الإطار النافذ.
- المصادر ذات السلطة.
- حالة المعايير القادمة/المشروعات.

### المرحلة 2: Trial Balance
- استيراد TB.
- تطبيع الأكواد والأسماء.
- مجموع مدين/دائن حتمي.
- كشف Missing/Duplicate/Unexpected negative/No movement/Round numbers/Suspense وغيرها.

### المرحلة 3: GL
- التوازن.
- القيود اليدوية.
- القيود بعد الإغلاق.
- القيود في تواريخ غير معتادة.
- المبالغ الكبيرة/المقربة/قبل حدود الأهمية.
- الأطراف/الحسابات النادرة.
- Reversals وأنماط الترحيل.

### المرحلة 4: Reconciliations
- TB ↔ GL.
- Subledger ↔ TB.
- Bank/AR/AP/Inventory/FA حسب التوفر.

### المرحلة 5: PBC
- قائمة ديناميكية مبنية على المخاطر والفجوات.
- كل مستند يرتبط بمخاطر وإجراء ونتيجة.

### المرحلة 6: Testing
- Sampling حتمي قابل للتكرار.
- إجراءات مراجعة.
- أدلة.
- Findings.
- Misstatements ISA 450.

### المرحلة 7: Council
إسناد:
- عضو واحد.
- عدة أعضاء.
- المجلس كله.

القواعد:
- جولة مستقلة عمياء.
- حجب حقول السلطة من AI.
- Consensus Matrix.
- اختلاف = نقطة تحقيق إضافية لا خطأ آلي.
- القرار النهائي بشري.

### المرحلة 8: Adjustments
- قيد مقترح.
- مصدر/سبب/مستند.
- حالة: proposed / accepted / rejected / posted.
- الترحيل لا يتم صامتاً.

### المرحلة 9: Financial Statements
- TB مصحح.
- خرائط القوائم.
- الإفصاحات.
- Cross-checks.
- إطار التقرير حسب الدولة والفترة.

### المرحلة 10: Report
- تقرير مسودة.
- ملخص تنفيذي.
- نتائج/تحريفات.
- Materiality.
- Evidence coverage.
- Human approval trail.

## Evidence Graph
كل شيء يرتبط كرسم أدلة:
`account → journal → document → evidence → risk → procedure → finding → adjustment → standard_ref → ai_opinion → human_decision → report`

لا توجد Finding نهائية بلا دليل أو سبب موثق، ولا رأي AI يتحول إلى سلطة.

## ما لا يفعله هذا التصميم
- لا يصحح نص معيار من الذاكرة.
- لا يعتبر كتاباً تدريبياً مصدراً إلزامياً.
- لا يساوي بين Exposure Draft ومعيار نافذ.
- لا يسمح للـAI بترحيل قيد أو إصدار رأي نهائي.
- لا يحذف نصاً متشابهاً لمجرد أنه يبدو مكرراً؛ الحذف الآلي محافظ ودقيق فقط.
